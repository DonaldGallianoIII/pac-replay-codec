PAC Replay Codec

Lossless. Up to 12.4× smaller*. Every byte back.

*Smaller files compress slightly worse.

⌂ Runs in this tab. Nothing is uploaded. This page and its code make no network requests, and the page's security policy blocks connections from it. The codec is plain JavaScript loaded with the page.

    What "exact" means here

    A packed file holds the size and the crc32 checksum of the original. Unpacking rebuilds the replay and checks both before it hands you anything. A damaged file fails with a message instead of coming back wrong.

    When you pack, this page also unpacks the result right away and compares it with your original, byte for byte, before it offers the download.

    How it gets so small

    A replay is a recording of a Colyseus game state, one patch per tick. The codec reads the game's own type table from the start of the file, then walks every field and predicts it from what came before: the same field on earlier ticks, the strings seen so far, and the game's own formulas for the carousel and portals. An adaptive binary range coder writes only the surprise. The decoder runs the same model in reverse.

    Costs and limits
    • CPU. About 0.3 s to pack and 0.2 s to unpack one 3.4 MB replay. zstd is faster; it copies, this models.
    • Whole file only. There is no seeking into the middle of a packed replay.
    • Game versions. Measured on 6.11 replays. The codec reads the type table from each file, so newer versions should pack; v7 replays are not yet tested.
    • Not a replay? It is kept as it was inside the container, so it still comes back exact.
